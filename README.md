# ЭТАЛОН ИИ: Автономный рабочий контур строгой инженерной разработки

Пакет содержит универсальный, вендор-нейтральный контур взаимодействия, правил, архитектурных шлюзов и научно-доказательной базы. Любой новый проект или ИИ-агент (независимо от модели: Claude, GPT, Gemini, Llama, DeepSeek или локальная LLM), инициализированный из этой директории, сразу начинает работу по строгим инженерным стандартам верификации без галлюцинаций и субъективных домыслов.

---

## 1. Универсальный запуск (Zero-Config Bootstrap для любой LLM / IDE)

Чтобы инициализировать любого нового ИИ-агента с эталонными правилами:

1. **Скопируйте файлы эталона в целевой проект:**
   * Скопируйте файлы `AGENTS.md`, `DECISIONS.md`, `HANDOFF.md`, `failure_index.json`, папку `rules/` и папку `KnowledgeBase/` в корень вашего проекта.
2. **Подключение к среде выполнения (любая среда):**
   * **Antigravity / Gemini CLI:** Скопируйте папку `.gemini\` в домашний каталог пользователя (`~/.gemini/antigravity/rules/`).
   * **Cursor / Windsurf / Copilot / Claude Code:** Ссылка на правила прописывается через `AGENTS.md` или `.cursorrules` / `CLAUDE.md` (достаточно указать: `Read AGENTS.md and rules/02_UNIVERSAL_AI_GOVERNANCE.md`).
   * **Custom Agent / AutoGen / CrewAI / LangGraph:** Подключите `AGENTS.md` и `rules/02_UNIVERSAL_AI_GOVERNANCE.md` как системный промпт (System Instructions).
3. **Первая инструкция любому новому ИИ (System Prompt / First User Prompt):**
   > «Ты работаешь в режиме строгого инженерного контроля.
   > 1. Соблюдай базовый контракт `AGENTS.md` и универсальный регламент `rules/02_UNIVERSAL_AI_GOVERNANCE.md`.
   > 2. Перед началом любой работы обязательно прочитай `HANDOFF.md`, `DECISIONS.md` и `failure_index.json`.
   > 3. До явного утверждения плана пользователем (`APPROVE <PLAN-ID>`) действует Gate 1 Read-Only Lock — изменение файлов проекта категорически запрещено.
   > 4. Запрещено делать утверждения об успехе без подтверждения сырым выводом терминала (`raw stdout`, `exit_code: 0`).
   > 5. Источник истины — файлы проекта на диске, а не память чата.»

## 2. Структура эталонного пакета

### Уровень L0–L3: Четырёхуровневая файловая память агента (Stateful File Memory)
* **`AGENTS.md` (L0 — Конституция):** Главный инвариантный контракт агента. Запреты на прямое редактирование без плана, запрет попутных правок (`side-fix`), обязательный цикл `verify -> checkpoint`.
* **`DECISIONS.md` (L1 — Архитектура):** Журнал архитектурных решений (ADR: контекст, выбор, отклонённые альтернативы).
* **`failure_index.json` (L2 — База сбоев):** Реестр подтверждённых инцидентов и запретов повторения доказанно неработающих вариантов (`disproven`).
* **`HANDOFF.md` (L3 — Мост сессий):** Фиксация текущего прогресса, верифицированных артефактов и точного следующего шага между перезапусками сессий.

### Глобальный регламент стоп-гейтов (Universal Governance)
* **`rules/02_UNIVERSAL_AI_GOVERNANCE.md`:** 10 фундаментальных стоп-гейтов разработки:
  1. `GATE 1 [Plan->Code | RO Lock]`: Защита от несанкционированной записи до утверждения плана.
  2. `GATE 2 [Atomic DAG]`: 1 намерение = 1 DAG-узел; изоляция изменений.
  3. `GATE 3 [No Big-Bang Rewrite]`: Запрет тотального переписывания работающих модулей.
  4. `GATE 4 [Proof of Work & Evidence-Only]`: Обязательное подтверждение терминалом (`exit_code: 0`).
  5. `GATE 5 [Read After Write — RAW]`: Контрольное чтение каждого файла после записи.
  6. `GATE 6 [Critic Never Repairs]`: Разделение генератора и аудитора; критик не чинит код сам.
  7. `GATE 7 [Universal Short Slug Rule]`: Короткие идентификаторы сессий и веток ($\le 20$ знаков).
  8. `GATE 8 [Resource & Token Guard]`: Экономия контекста, последовательный вызов ролей.
  9. `GATE 9 [Mandatory Auto-Handoff]`: Автономная фиксация состояния по завершении задачи.
  10. `GATE 10 [Fail-Closed]`: Отказ по умолчанию при любых сомнениях или превышении лимитов.

### Научно-доказательная база (KnowledgeBase)
* **`KnowledgeBase/manifest.yaml`:** Манифест версий, хэшей и реестра доказательств.
* **`KnowledgeBase/claims/`:** Атомарные карточки клеймов со строгими цитатами:
  * `CLAIM-0001` (Google DeepMind 2023): Деградация рассуждений при самокоррекции без внешнего фидбека.
  * `CLAIM-0002` (Penn State 2024): Работоспособность самокоррекции только при надёжном внешнем оракуле.
  * `CLAIM-0003` (TraceDev 2026): Прирост +186.64% качества при графе трассируемости артефактов.
  * `CLAIM-0004` (Formal Verification 2025): Сложность верификации мультиагентных систем.
  * `CLAIM-0005` (SWE-Gate 2024): 34.3% скрытых сбоев при успешном прохождении функциональных тестов.
  * `CLAIM-0006` (Arch Intent 2026): Коэффициент вариации архитектурного графа при генерации.
  * `CLAIM-0007` (Self-Refine 2023): 94% сбоев вызваны ошибочным фидбеком модели, а не реализацией.
  * `CLAIM-0008` (Self-Refine 2023): 94% ложных вердиктов «всё в порядке» в строгих рассуждениях.
  * `CLAIM-0009` (SEI CMU 2016): Пропуск интеграционных и ресурсных зависимостей при локальном анализе.
  * `CLAIM-0010` (KTH/KIT 2025): Исследовательский пробел (research gap) в автономной оценке архитектурного соответствия силами LLM.
* **`KnowledgeBase/rules/00_core/R001_critic_never_repairs.md`:** Первое доказанное критическое правило (разделение ролей генератора и оценщика).
* **`KnowledgeBase/policies/`:** Каталог исполняемых политик (Rego / Python middleware).

## 3. Ключевые инварианты поведения

1. **Fail-Closed:** Любое действие по умолчанию заблокировано, если нет положительного доказательства валидности.
2. **Stateless Generator vs Local Engine Authority:** ИИ рассматривается как вычислитель без постоянного состояния; авторитетным источником состояния и гейтов является локальный движок проекта на диске.
3. **Raw-Before-Summary:** Сначала сырой вывод терминала или файла (`raw stdout`), затем выводы.
4. **Side-Fix Ban:** Запрещено попутно чинить несвязанные участки кода; все замечания фиксируются в бэклог.

## 4. Удалённый шлюз (Remote Gateway) и мультимодальное зрение

- **Универсальный шлюз (`scripts/chat_bridge.py`):** модуль приёма входящих сообщений (Telegram и внешние каналы). Запуск: `python scripts/chat_bridge.py listen`.
- **Изоляция пользователей (`scripts/sandbox_manager.py`):** каждый собеседник изолирован в своей песочнице `sandboxes/users/<user_id>/`.
- **Контроль доступа:** строгие команды админа `/allow <id>` (добавить пользователя) и `/deny <id>` (заблокировать). Неизвестные пользователи ждут подтверждения.
- **Мультимодальное зрение (Gemini 2.5 Flash):** чистое распознавание изображений, чтение надписей, анализ схем и таблиц без генеративных нейросетей.
- **Манифест зависимостей (`requirements.txt`):** зафиксированы библиотеки окружения.
