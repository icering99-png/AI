## FIX-03 [P0] Генератор манифеста — убрать ложь из метрики

**Что:** `state_manifest.json` содержит 1 запись, а ADR-026 и HANDOFF заявляют «27 модулей, Zero Drift». RegressGuard верифицирует против пустого манифеста — это validation theater.

**Как:** создать `scripts/build_manifest.py`:

```python
"""Regenerate state_manifest.json from actual core/ contents."""

import hashlib
import json
from pathlib import Path

ROOT = Path(__file__).resolve().parent.parent


def hash_file(p: Path) -> str:
    """Stream file content into SHA-256 hex digest."""
    h = hashlib.sha256()
    with p.open("rb") as f:
        for chunk in iter(lambda: f.read(65536), b""):
            h.update(chunk)
    return h.hexdigest()


def main() -> None:
    """Write manifest with one hash per core module."""
    entries = {}
    for p in sorted((ROOT / "core").glob("*.py")):
        entries[str(p).replace("\\", "/")] = hash_file(p)
    out = ROOT / "state_manifest.json"
    out.write_text(json.dumps(entries, indent=2, ensure_ascii=False) + "\n", encoding="utf-8")
    print(f"manifest written: {len(entries)} modules")


if __name__ == "__main__":
    main()
```

Выполнить: `python scripts/build_manifest.py`

**Критерий:** вывод `manifest written: N modules`, где N == количеству `core/*.py`; запись зафиксирована коммитом `chore: regenerate state manifest from core/`.

## FIX-04 [P1] Зеркала — собирать скриптом, не руками

**Что:** три копии правил (root, TEMPLATE_PORTABLE, .gemini) синхронизировались вручную и уже разъехались: `.gemini` содержит устаревшую русскую версию регламента, README отправляет пользователей именно к ней.

**Как:** создать `scripts/build_mirror.py`:

```python
"""Rebuild TEMPLATE_PORTABLE and .gemini mirrors from canonical sources."""

import shutil
from pathlib import Path

ROOT = Path(__file__).resolve().parent.parent
TPL = ROOT / "TEMPLATE_PORTABLE"

COPY_DIRS = ["core", "rules", "schemas", "tests", "prompts", "KnowledgeBase", "scripts"]
COPY_FILES = ["AGENTS.md", "DECISIONS.md", "README.md", "failure_index.json", "state_manifest.json", "pyproject.toml"]
IGNORE = shutil.ignore_patterns("__pycache__", "*.pyc", ".pytest_cache")


def sync_tpl() -> None:
    """Refresh portable template from canonical root."""
    for d in COPY_DIRS:
        src = ROOT / d
        if src.is_dir():
            shutil.rmtree(TPL / d, ignore_errors=True)
            shutil.copytree(src, TPL / d, ignore=IGNORE)
    for f in COPY_FILES:
        if (ROOT / f).is_file():
            shutil.copy2(ROOT / f, TPL / f)


def sync_gemini() -> None:
    """Refresh .gemini rule mirror from canonical rules/."""
    gem = ROOT / ".gemini" / "antigravity" / "rules"
    gem.mkdir(parents=True, exist_ok=True)
    for r in (ROOT / "rules").glob("*.md"):
        shutil.copy2(r, gem / r.name)


def main() -> None:
    """Build all mirrors and report."""
    sync_tpl()
    sync_gemini()
    print("mirrors rebuilt: TEMPLATE_PORTABLE + .gemini")


if __name__ == "__main__":
    main()
```

Порядок навсегда: `build_manifest.py` → `build_mirror.py` → коммит. Зеркала больше никогда не правятся руками.

**Критерий:** `diff rules/02_UNIVERSAL_AI_GOVERNANCE.md .gemini/antigravity/rules/02_UNIVERSAL_AI_GOVERNANCE.md` — пусто; `diff -r core TEMPLATE_PORTABLE/core` (без `__pycache__`) — пусто.

**Что:** моддинг возвращается в эталон (наследие universal-modder из ADR-003) — но профилем, не в ядро. У модов своя специфика повторяющихся ошибок: версии игры после патчей, порядок загрузки, конфликты ассетов, регистр путей, кодировки локализаций.

**Как:**

1. `rules/profiles/MODDING.md` — правила домена: структура мода обязательна к проверке; правка чужих файлов ядра игры запрещена (только оверлеи); каждый собранный мод проходит валидатор + smoke-запуск; ссылка на официальный док-репозиторий инструментов игры — первоисточник.
2. `schemas/model_registry.json` — домен `modding`: локальный вес для рутины, облачная модель для анализа конфликтов; `allowed_paths: ["mods/", "tools/modval/"]`.
3. `tools/modval/` — детерминированный валидатор модов:
   - структура: манифест, обязательные файлы, целостность архива;
   - конфликты: два мода меняют один и тот же ассет → WARN/FAIL;
   - load order: известные правила порядка → линт;
   - smoke-запуск: запуск игры с одним модом, скан лога на ошибки, exit_code/таймаут.
4. Фикстуры из FIX-15 (`mods/conflict_pair/`, `mods/bad_loadorder/`) — эталон «обязано быть поймано».

**Критерий:** валидатор отклоняет все фикстуры галереи и принимает эталонный корректный мод; правка правил моддинга идёт только через шлюз (Candidate → APPROVE), факты (записи ошибок, фикстуры) добавляются свободно.

## FIX-20 [P0] Хук: сначала шпион, потом реальные имена инструментов

**Что:** `.agents/hooks.json` ловит `edit_file|write_file|run_command` с путём в аргументе `Path` — а в Antigravity файлы пишут инструменты `write_to_file`, `replace_file_content`, `multi_replace_file_content`, путь — в `TargetFile`. Итог по прожарке: **0 реальных блокировок записи**; тесты зелёные, потому что кормят хук выдуманным форматом. Плюс путь `python ../core/pre_tool_guard.py` относительный.

**Как:**
1. День 1 — хук-шпион: пишет в `logs/hook_calls.jsonl` ВСЁ, что получает (имя инструмента, аргументы), ничего не блокирует. Поработать в IDE один день.
2. Посмотреть реальные имена инструментов/аргументов в логе — и только потом переписать matcher и `eval_tool()` под них.
3. Абсолютный путь к скрипту (или якорь от манифеста). Решение о допуске — НЕ по файлам, которые агент может править.

**Критерий:** в логе шпиона есть реальные вызовы записи файлов из IDE; после включения блокировки попытка правки защищённого файла в IDE реально отклоняется (скрин/лог).

## FIX-21 [P0] Закрыть дыру само-одобрения

**Что:** `pre_tool_guard` всегда разрешает писать `plans/PLAN-LIVE.md`, а решение «можно ли править код» принимает по строке `Status:` в ЭТОМ ЖЕ файле. Атака из прожарки: пишем в план `Status: APPROVED, Allowed Paths: *` — и можно править что угодно, включая сам `hooks.json`. Токен `APPROVE <PLAN-ID>` хук не проверяет ни разу. Контроль не может храниться там, куда пишет контролируемый.

**Как (по возрастанию надёжности):**
1. Минимум: статус плана хранить вне досягаемости агента (`.git/info/plan-state`, переменная окружения, настройка IDE), а не в `plans/`.
2. Норма: вообще не пытаться держать RO-lock хуком — использовать Permissions Antigravity (allow/deny/ask; всё неразрешённое — ask) + защиту ветки main + PR-ревью человеком. Хук оставить только как лог.
3. Запретить правку `.agents/hooks.json` и правил на уровне Permissions, не на уровне текста правил.

**Критерий:** сценарий прожарки (сам записал APPROVED в план → просит правку кода) больше не проходит; правило сформулировано как «запрещено, потому что…», а не «STRICTLY PROHIBITED».

## FIX-22 [P0] Обезвредить тест, который делает git checkout -f в рабочей папке

**Что:** `tests/test_branch_guard.py` вызывает настоящий `BranchGuard.abort_hypo()`, а тот выполняет `git checkout -f main` (core/branch_guard.py) в текущей папке проекта. Сегодня мина спит только потому, что ветки `main` нет; как появится — каждый прогон тестов станет молча откатывать незакоммиченную работу (проверено прожаркой вживую: строка в DECISIONS.md исчезла).

**Как:** тест создаёт временный репозиторий (`tempfile.TemporaryDirectory()` + `git init -q` + начальный коммит + `git checkout -b main`) и вызывает `abort_hypo` с `cwd` этого репозитория. Рабочую папку тесты не трогают ВООБЩЕ.

**Критерий:** тест зелёный во временном репо; `git status` основного репо после прогона тестов идентичен состоянию до прогона.

## FIX-23 [P1] Командный фильтр: чёрный список → белый

**Что (проверено прожаркой на живом хуке):** `rm -rf /`, `Remove-Item -Recurse -Force C:\Users`, `git push --force`, `python -c "open('AGENTS.md','w')…"`, `pip install evil` — **allow**; `git fetch`, `git gc`, `pip show requests`, `find . -name '*.py'` — **deny**. Чёрный список в принципе необходуем (PromptArmor: Gemini в Antigravity уже обходил запрет через `cat`). `chk_danger` пропускает `os.system('rm -rf /')`, `shutil.rmtree('/')`, `subprocess.run(['format','C:'])`, но банит безобидный `getattr` в собственном же escalation_router.

**Как:** белый список команд в конфиге: `python -m pytest/unittest`, `ruff`, `mypy`, `git status/diff/log/show`, `node`, `npm test` — всё остальное → ask/deny через Permissions IDE. Регексы-детекты удалить. Разрушительные операции (push, reset --hard, удаление) — только руками человека.

**Критерий:** таблица из прожарки инвертировалась: `rm -rf /` → deny, `git fetch`/`git gc` → allow; нет ни одной команды, которая проходит фильтр и при этом разрушительна.

## FIX-24 [P1] Диета инструкций по прожарке: 145 приказов → один экран

**Что:** ≈145 слов-приказов и ≈76 000 символов обязательного bootstrap (HANDOFF 455 строк + DECISIONS + failure_index) — модель тонет в правилах («How Many Instructions…»: даже лучшие модели держат ~68% из 500 инструкций; Lost in the Middle). Правила противоречат друг другу: FAIL-0007 (APPROVE на каждый шаг) vs FAIL-0009 (не останавливаться); Gate 1 «пиши план сам» vs «не склеивай план и правку»; gauntlet_loop «итерируй без вмешательства» vs «1 шаг = 1 файл»; «No Artificial Character Limits» vs лимиты 300/15/20. CAPS и «категорически» делают хуже: Google прямо пишет — Gemini 3 любит прямые ясные инструкции без чрезмерной настойчивости.

**Как:**
1. Переписать AGENTS.md на 40–80 строк по образцу со стр. 17 прожарки: Проект → Как проверить (2 команды) → Как работаем (4–5 пунктов) → Чего не делать и ПОЧЕМУ (4 пункта с «зачем») → Стиль → Формат отчёта. Спокойный тон, ноль жаргона (ITV, RAW, fite, STE-100 — в архив).
2. `rules/02_UNIVERSAL_AI_GOVERNANCE.md` удалить (второй экземпляр тех же гейтов) или слить с AGENTS.md.
3. Перенести правила в `.agents/rules/*.md` с ключом `trigger` (always_on / model_decision / glob / manual) — папка `rules/` в корне средой НЕ загружается. Лимиты: 24 000 байт на файл, бюджет 20 000 токенов на постоянные правила.
4. HANDOFF → 20 строк, failure_index → 5 строк «что не сработало»; всё историческое — в docs/archive/ (историю хранит git log).
5. Противоречия: оставить одну версию каждого правила; правило-заплатка после инцидента — сначала вычеркнуть старое, потом добавить новое.

**Критерий:** `wc -c` постоянных правил ≤ 24 000 байт на файл; в AGENTS.md ≤ 80 строк и ноль пар противоречащих правил; каждое критичное правило дублировано механизмом (Permissions/CI/защита ветки), а не только текстом.

## FIX-25 [P2] Честность ядра: мёртвые модули и заглушки

## FIX-26 [P2] Журнал аудита: признать, что он не защищён, или сделать HMAC

**Что:** AuditLogger строит цепочку SHA-256 без секретного ключа: любой, кто пишет в файл (то есть сам агент), правит запись и пересчитывает хеши — `verify_log()` отвечает VALID. Плюс `details={"status": "PASS"}` затирает основной `status="FAIL"`.

**Как:** вариант А (честный): убрать из документации слова «защита от подделки», журнал — просто журнал, поле details не может перезаписывать статус. Вариант Б (настоящий): HMAC с ключом вне репозитория (переменная окружения), журнал там, куда агент не пишет. Настоящий арбитр всё равно CI/GitHub.

**Критерий:** воспроизведение атаки прожарки (правка записи + перехеш → verify) либо невозможна (HMAC), либо документация больше не называет журнал защищённым.

## FIX-27 [P3] Карточки источников: приписывания и хвосты

**Что:** «слепа в 94% случаев» приписано Huang et al., а это Self-Refine (Madaan et al., ChatGPT-математика 2023); «LBYL отсекает 80%» — без карточки-источника; у CLAIM-0004 в manifest.yaml ID 2501.12345 (заготовка), в карточке 2608.03609. Хвосты CAD/3D из текстов убрать (3D вернётся профилем THREED по FIX-11).

**Критерий:** каждая цифра в правилах имеет карточку с точной цитатой и корректным автором; ни один вывод не шире своей цитаты.
