# План интеграции ядра «Эталон ИИ» (PLAN-INT-001.md)

> **Статус:** DRAFT / На согласовании (Интегрированы агенты ведения плана на диске и квантования подпланов).  
> **Цель:** Развертывание локального состязательного ядра (Local-First) с защитой от дурака, стражем регрессий, живым древовидным планом на диске, квантованием подпланов по $\le 30$ строк diff и экономным микро-шлюзом эскалации к Gemini.

---

## 1. SCOPE (Создаваемые компоненты)

| Файл | Роль / Назначение | Ограничения и инварианты |
| :--- | :--- | :--- |
| `core/defense_guard.py` | Детерминированный барьер TIER_0 (AST-контроль, sandbox путей, лимит $\le 30$ строк diff, запрет деструктивных операций, **проверка длины идентификаторов $\le 15$ символов**, **проверка физического существования путей/ссылок на диске**). | Выполняется первым на CPU (0% внешних токенов). Чистый Python (`ast`, `pathlib`). |
| `core/rules_critic.py` | Независимый логический аудитор (Blind Review). Валидация по `schemas/critic_verdict.json`, проверка стоп-гейтов 1–10 и базы сбоев `failure_index.json`, канареечные ловушки (Canary Traps). | Строго Read-Only. Сам код не чинит. Возвращает только `PASS` или `REJECT`. |
| `core/regression_guard.py` | Страж регрессий и обратной совместимости. Запуск золотых тестов (`tests/golden/`), сверка с `failure_index.json` (L2) и верификация контрольных сумм по `state_manifest.json`. | Блокирует любые коммиты, ломающие ранее созданную функциональность. |
| `core/plan_architect.py` | Агент-Архитектор плана. Ведение живого мастер-плана на диске (`plans/PLAN-LIVE.md`), перенос завершенных этапов в нижний архив без удаления, версионирование изменений. | Запрещено держать план только в памяти чата. План — физический файл на диске. |
| `core/subplan_decomposer.py` | Агент-Декомпозитор подпланов. Древовидное квантование задачи на атомарные подпланы с жестким лимитом $\le 30$ строк diff каждый, удержание фокуса только на текущем активном подплане. | 1 подплан = 1 намерение = $\le 30$ строк diff. Бесшовный старт в новом чате по следующему незакрытому подплану. |
| `core/escalation_router.py` | Шлюз эскалации и языковой мост. Локальный цикл отладки (макс. 3 раунда). Сериализация в микро-пакет по `schemas/escalation_packet.json` ($\le 300$ симв.). Языковой мост: русское ТЗ $\to$ английский контекст $\to$ русский итоговый отчет. | Абсолютный лимит $\le 300$ символов на весь JSON (`g`, `c`, `e`, `w`). Максимум 2 попытки эскалации. Кэширование решений в `GUIDANCE-XXXX`. |
| `core/runner.py` | Локальный координатор пайплайна (`Worker -> Defense Guard -> Regression Guard -> Plan Decomposer -> Critic -> Router`). | Детерминированное управление переходами состояний. |
| `tests/test_local_pipeline.py` | Набор сквозных тестов консилиума, планировщиков и защиты от дурака. | Проверка штатного прохода (0 токенов), отсева длинных имен (>15 симв.), битых путей, архивации плана и эскалации. |

## 2. МЕХАНИЗМЫ ПАМЯТИ, ПЛАНИРОВАНИЯ И ЗАЩИТЫ ОТ РЕГРЕССИЙ

1. **Живой древовидный план на диске (`plans/PLAN-LIVE.md`):**
   * **Верх:** Статус и текущий фокус (Active Subplan $\le 30$ строк diff).
   * **Середина:** Дерево оставшихся подпланов в формате DAG.
   * **Низ (Архив завершенного):** Все выполненные шаги перемещаются вниз с датой, доказательствами (`exit_code: 0`, хэши) и **никогда не удаляются**.
2. **Золотые инварианты (`tests/golden/`):**
   * Каждый подтвержденный рабочий модуль получает неизменяемый тест-инвариант.
   * `Regression Guard` прогоняет `tests/golden/` перед фиксацией любого нового кода.
3. **База сбоев (`failure_index.json` — L2 память):**
   * Все выявленные ошибки и дефекты заносятся в реестр с правилом-запретом.
   * Повторение ошибок со статусом `disproven` блокируется автоматически.
4. **Реестр решений (`DECISIONS.md` — L1 память):**
   * Фиксация архитектурных стандартов в формате ADR.
5. **Слепок целостности (`state_manifest.json`):**
   * SHA-256 хеши неизменяемых утвержденных файлов. Запрет случайного изменения чужого кода.

## 3. DEPENDENCIES & RISKS (Зависимости и риски)

* **Зависимости:**
  * Стандартная библиотека Python 3.12 (`ast`, `json`, `pathlib`, `re`, `sys`, `hashlib`).
  * Полное отсутствие внешних тяжелых пакетов для мгновенного локального старта (<50 мс).
* **Риски и их нейтрализация:**
  1. *Переполнение лимита 300 символов (`PAYLOAD_OVERFLOW`):* Детектор размера блокирует отправку в облако. Fail-Closed откат.
  2. *Засыпание критика (Review Fatigue):* Внедрение мутационных canary-проверок со сломанным кодом.
  3. *Зацикливание отладки (Retry Loop):* Жесткий счетчик — ровно 3 локальных раунда, затем точечная эскалация.
  4. *Потеря контекста при смене чата:* `Plan Architect` восстанавливает состояние мгновенно из `plans/PLAN-LIVE.md`.

## 4. ATOMIC DAG (Пошаговый граф задач)

```text
[Шаг 1: Defense Guard] ──► [Шаг 2: Rules Critic] ──► [Шаг 3: Regression Guard]
(AST, <=15 симв, пути)        (Blind JSON + Canary)       (Golden tests + L1/L2)
                                                                 │
                                                                 ▼
[Шаг 7: RAW & Handoff] ◄── [Шаг 6: Runner & Тесты] ◄── [Шаг 5: Escalation Router] ◄── [Шаг 4: Plan Architect & Decomposer]
                           (Сквозной консилиум)        (3 раунда, <=300 симв, RU-EN)  (Живой план на диске, subplans <=30)
```

1. **Шаг 1: `core/defense_guard.py`**
   * `check_syntax_ast(code)`
   * `check_ident_length(code, max_len=15)`
   * `check_path_liveness(target_path, root_dir)`
   * `check_diff_size(diff_text, max_lines=30)`
   * `check_destructive_ops(code)`
2. **Шаг 2: `core/rules_critic.py`**
   * Слепой аудит по схеме `schemas/critic_verdict.json`.
   * Canary-детектор (отлов сговора и лени критика).
3. **Шаг 3: `core/regression_guard.py`**
   * Прогон `tests/golden/`.
   * Сверка с `failure_index.json` и `state_manifest.json`.
4. **Шаг 4: `core/plan_architect.py` и `core/subplan_decomposer.py`**
   * Создание и ведение `plans/PLAN-LIVE.md`.
   * Квантование задач на подпланы с лимитом diff $\le 30$ строк.
   * Функция ротации: перемещение завершенного шага в нижний архив без удаления и сдвиг фокуса.
5. **Шаг 5: `core/escalation_router.py`**
   * Локальный счетчик отладки (до 3 раунда).
   * Упаковка микро-пакета $\le 300$ символов по схеме `schemas/escalation_packet.json`.
   * Языковой мост (RU вход $\to$ EN технический пайплайн $\to$ RU выход).
6. **Шаг 6: `core/runner.py` и `tests/test_local_pipeline.py`**
   * Интеграция консилиума в единый цикл.
   * Сквозные тесты:
     * Тест 1: Зеленый проход (0 облачных токенов).
     * Тест 2: Отсев имен $>15$ символов.
     * Тест 3: Отсев несуществующих/битых путей.
     * Тест 4: Блокировка регрессий при поломке Golden теста.
     * Тест 5: Работа живого плана (квантование подпланов $\le 30$ строк, архивация вниз).
     * Тест 6: Успешная эскалация микро-пакетом $\le 300$ символов при локальном тупике.
     * Тест 7: Fail-Closed при превышении лимита попыток.
7. **Шаг 7: Верификация, RAW и фиксация в `HANDOFF.md`**
